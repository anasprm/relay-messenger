# Deploying Relay

Relay is two services:

| Piece | Host | What it does |
|---|---|---|
| Web app (Next.js) | **Vercel** (free Hobby plan) | UI, landing page, chat client |
| API + Socket.io (Express) | **Render** (free web service) | Auth, messages, uploads, presence, WebRTC signalling |
| Data | **Firebase** (Spark plan) | Firestore database + rules |

Firebase Storage is optional and only needs the Blaze plan when you want uploads to survive API restarts. Without it, uploads are written to the API's local disk and disappear when a free Render service spins down.

> **Never commit** `server/data/firebase-service-account.json` or any base64 version of it. It is gitignored — keep it that way.

---

## 0. Prerequisites

- The repo pushed to GitHub (`anasprm/relay-messenger`).
- The Firebase project `relay-messenger-anasprm` with the Firestore database `default` (already configured).
- A free [Vercel](https://vercel.com) account and a free [Render](https://render.com) account, both connected to GitHub.

---

## 1. Deploy the API to Render

### 1a. Create the service from the blueprint

1. Render Dashboard → **New → Blueprint**.
2. Connect the GitHub repo and select the branch `main`.
3. Render reads [`render.yaml`](./render.yaml) and shows one service, `relay-api`.
4. Apply the blueprint.

If you prefer a manual service instead:

| Setting | Value |
|---|---|
| Type | Web Service |
| Runtime | Node |
| Root Directory | *(repository root — leave blank)* |
| Build Command | `npm ci` |
| Start Command | `npm run start:server` |
| Health Check Path | `/api/health` |
| Instance Type | Free |

### 1b. Add the environment variables

`render.yaml` already defines the non-secret variables. Fill in the two secrets it marks as required:

**`FIREBASE_SERVICE_ACCOUNT_BASE64`** — run this in PowerShell from the repository root:

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("server\data\firebase-service-account.json"))
```

Copy the single-line output into the Render variable. On macOS/Linux:

```bash
base64 -w0 server/data/firebase-service-account.json
```

**`CLIENT_ORIGIN`** — set it to the Vercel URL once step 2 is done. Until then use a placeholder such as `https://example.vercel.app`; the API starts fine either way.

Also verify:

| Variable | Value |
|---|---|
| `FIREBASE_PROJECT_ID` | `relay-messenger-anasprm` |
| `FIREBASE_FIRESTORE_DATABASE` | `default` (literal — **not** `(default)`) |
| `SESSION_SECRET` | generated by Render (keep it stable) |
| `NODE_VERSION` | `20.11.1` |
| `NODE_ENV` | `production` |

`PORT` is injected by Render; do not set it.

### 1c. Wait for the first deploy

The build runs `npm ci`, then the API starts, hydrates Firestore, regenerates seed media, and logs:

```
Relay API listening on http://localhost:10000
Database: firestore (relay-messenger-anasprm/default) · 5 users · ...
```

Open `https://<service>.onrender.com/api/health`. It should return `"ok": true` and `"database": "firestore"`. Copy the service URL — it is needed for Vercel.

## 2. Deploy the web app to Vercel

1. Vercel Dashboard → **Add New → Project** → import `anasprm/relay-messenger`.
2. Configure:

| Setting | Value |
|---|---|
| Framework Preset | Next.js |
| Root Directory | `web` |
| Build Command | *(leave default — `web/vercel.json` overrides it)* |
| Output Directory | *(leave default)* |
| Install Command | *(leave default — `web/vercel.json` overrides it)* |

3. Add the environment variable:

| Name | Value | Environments |
|---|---|---|
| `NEXT_PUBLIC_API_URL` | `https://<service>.onrender.com` | Production, Preview, Development |

4. Deploy.

The build runs `npm ci` at the repo root and `npm run build -w web`, then serves the statically generated pages.

---

## 3. Connect the two

1. Copy the Vercel production domain, e.g. `https://relay-messenger.vercel.app`.
2. Render → `relay-api` → **Environment** → set:

   ```
   CLIENT_ORIGIN=https://relay-messenger.vercel.app
   ```

   Add multiple origins comma-separated if you also use a custom domain or stable preview URL:

   ```
   CLIENT_ORIGIN=https://relay-messenger.vercel.app,https://relay.example.com
   ```

3. Save — Render redeploys automatically. Without this step the browser blocks the API and Socket.io with a CORS error.

---

## 4. Verify the public deployment

1. `https://<service>.onrender.com/api/health` → `ok: true`, `database: firestore`.
2. Open the Vercel URL — the welcome page loads.
3. Sign in with `demo / demo123`.
4. Open the same URL in a second browser profile as `alice / alice123`.
5. Send a message: it should appear instantly in both windows, with presence and typing indicators.
6. Send an image or file, then reload the page and confirm the attachment still renders.
7. Toggle **Official / Minimal** and light / dark; the choice survives a reload.
8. Open a thread and check that the seeded voice note and preview image load.

If messages send but realtime does not update, the Socket.io origin is blocked. If nothing loads at all, `NEXT_PUBLIC_API_URL` is missing — it is baked in at build time, so change it and redeploy the Vercel project.

---

## Optional: custom domains

- Vercel → Project → **Domains** → add `relay.example.com`.
- Render → Service → **Settings → Custom Domains** → add `api.relay.example.com`.
- Then set `NEXT_PUBLIC_API_URL=https://api.relay.example.com`, update `CLIENT_ORIGIN`, and redeploy both.

## Free-tier behaviour

| Behaviour | Effect |
|---|---|
| Cold start | Render free services sleep after ~15 minutes of inactivity; the first request can take 30–60 seconds. Socket.io reconnects automatically. |
| Ephemeral disk | Local uploads and generated seed media are wiped on restart/redeploy. Seed media regenerates on every boot; **user uploads do not**. |
| Firestore quota | Spark plan quotas are plenty for a demo; data itself is durable. |
| Sessions | Signed with `SESSION_SECRET`; if it changes, everyone is signed out. |

### Making uploads durable

Enable the Blaze plan, create a Cloud Storage bucket, then add to Render:

```
FIREBASE_STORAGE_BUCKET=relay-messenger-anasprm.firebasestorage.app
```

Restart the API and confirm `/api/health` reports `"storage": "firebase"`. No client changes are needed.

## Troubleshooting

| Symptom | Fix |
|---|---|
| `database: json` in health | The base64 key is wrong or Firestore is unreachable. Decode it locally and confirm `project_id`, `client_email`, and `private_key` exist. |
| CORS error in the browser console | `CLIENT_ORIGIN` must exactly match the browser origin (`https`, no trailing slash). |
| `5 NOT_FOUND` from Firestore | `FIREBASE_FIRESTORE_DATABASE` must be `default`, not `(default)`. |
| API exits on boot | Check Render logs for `firebase` credential errors. Remove stray quotes or line breaks from the base64 value. |
| Build fails on Vercel | Make sure Root Directory is `web` and `package-lock.json` is committed at the repo root. |
| Welcome page works but sign-in fails | `NEXT_PUBLIC_API_URL` points to the wrong host, or the API is still asleep. |

---

## Updating

Push to `main` — Vercel and Render both redeploy automatically. Rules changes are separate:

```bash
npx firebase-tools deploy --only firestore:rules,storage
```
